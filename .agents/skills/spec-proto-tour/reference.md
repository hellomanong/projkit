# spec-proto-tour 参考

按需查，不要预先全读。§一 数据格式，§二 写法，§三 常见错误，§四 复审清单，§五 数据目录的 README。

## 一、数据格式

数据目录里：`data-0-meta.js`（模块词表、现状标记、全局说明，从 `assets/data-0-meta.template.js` 复制）+ 若干 `data-N-<区域>.js`（每个文件推入若干屏）。`build.py` 按文件名排序拼接。

### 视图（一屏或一个抽屉）

```js
window.AGS_ANNO_VIEWS.push({
  id: 'gw-prov',                       // 唯一标识
  group: 'Administration › Gateway',   // 目录页分组
  screen: 'Administration · Gateway',  // 原型里的 data-screen-label，用来识别当前屏
  when: { text: 'LLM providers' },     // 可选：同一 screen 下区分标签页，要求根元素文字里含这段
  drawer: true,                        // 可选：抽屉或弹层；打开时只显示它的圆点，面板自动停到左侧
  title: 'Gateway › LLM Providers',    // 面板标题
  path: 'Administration › Gateway › LLM Providers 标签',  // 手动打开的路径
  go: [['nav', 'Administration'], ['nav', 'Gateway'], ['exact', 'LLM Providers', 'Administration · Gateway']],
  intro: '这一屏讲什么……',
  items: [ /* 功能点 */ ]
});
```

`go` 是「带我去」的点击步骤，每步一个数组：`['nav', '侧栏文字']`（整段文字相等）、`['exact', '文字', 屏幕标签]`、`['click', '包含的文字', 屏幕标签]`、`['title', 'title 属性片段', 屏幕标签]`；可加第四项选第几个匹配（从 0 开始）。

### 功能点

```js
{
  t: 'Reliability：供应商出错时，这个 Provider 怎么自保',  // 标题：界面上的英文名 + 一句白话
  ph: 'P0', phText: 'P0（完整性基线 P1）',   // 阶段：P0 / P1 / P2 / NA；phText 可覆盖标签文字
  a: { text: 'connection semantics' },       // 锚点，见下
  how: '点底部 Continue 进入第 2 步',          // 可选：元素要先操作才出现时，写怎么让它出现
  what: '……',                                // 功能解释（主体）
  mods: [['gc-gw', '保存超时、重试、冷却参数'], ['litellm', '（目标）执行这些参数']],  // 归属模块
  st: ['part', '四个值只保存在 GC，既不下发也不执行'],   // 现状
  talk: '……',                                // 一句话说清
  warn: '……'                                 // 注意：原型与 PRD、设计不一致或待决
}
```

锚点 `a` 在当前屏的根元素内查找，三选一：`{ text }` 文本包含、`{ exact }` 文本完全相等、`{ title }` 元素 `title` 属性包含；同样的文字出现多次时加 `nth`，要挂到外层元素时加 `up`。锚点优先选界面上稳定、唯一的文字；按钮的 `title` 提示往往比按钮文字更唯一。原型里本身带编号的文字（例如按钮上写着需求编号）可以当锚点，它是原型原文，不算往讲解里写编号。

文字字段支持 `**粗体**`、`` `代码` ``、`\n` 换行；不能出现 `</script`。`mods`、`st` 可以整栏不写（项目没有后端时），页面就不显示这两栏。

## 二、写法

### 功能解释（what）

- 从用户的角度回答三件事：这是什么；你在这里能做什么；做了之后会发生什么。不写「为什么要有这一节」，不写「PRD 要求……验收……」这种规格腔。
- 讲解不是翻译。界面上列着几个参数，就讲清每个参数的意思、取值大小的后果、几个概念怎么配合，不能把名词翻成中文罗列一遍就完。
- 尽量用原型里现成的数据举一个具体例子，并在相关的几张卡里复用同一个例子，讲的时候前后能接上（例如同一个 Provider 连续超时，进入冷却，流量换到备用模型，多花的钱出现在成本页）。
- 一句只说一件事；超过三项的列举改成分行，用 `\n\n` 分段，每段可以用「**粗体引导语**：」开头。卡片之间不必统一格式，简单的功能两三句就够。
- 界面上真实出现的英文标签保留（讲的时候要指着它）；内部词换成白话，实在绕不开的词第一次出现时用半句话解释。常见替换：准入写成「能不能用」；裁决写成「放行还是拦截的判定」；登记写成「记进台账」；审计写成「留下操作记录（谁在什么时候改了什么）」；期望态写成「网关配置」；策略包写成「规则包（所有规则打成的一个包）」；深链写成「直接跳到」。
- PRD 规定了、原型还没画出来的能力，写明「按产品要求……原型这一页只画了……」，不要写成原型已有。

### 一句话说清（talk）

讲给听众的一句白话，不是给讲解人的提示（不写「讲的时候说……」「这张表值得先放出来」）。设计目标加「按设计」或「目标是」。不是每张卡都要有。

### 归属模块（mods）与现状（st）

- 模块键只能取词表里的；动作写一句白话，说这个模块在本功能里做什么。还没做的设计目标以「（目标）」开头，页面显示成虚线标签和灰字；已有的部分和目标部分拆成两条，不写在一条里。
- 现状五档：`done` 已实现、`part` 部分实现、`no` 未实现、`na` 设计未覆盖、`out` 不在本次范围。一句话只写能在仓库里核对的事实，不写接口路径、契约编号、文件名。
- 判档回到代码核对，不凭设计文档推断「已实现」；接口返回「未实现」、只存储不执行、前端控件停用，都不是 `done`。

### 注意（warn）

只写三类：原型与 PRD 不一致；原型与设计或代码不一致；待决、未定义。可以写「PRD 2.10」这样的版本名，不写编号。原型内部数据互相矛盾时，引用原文，不替它推断哪个对。

### 阶段（ph）

按 PRD 标：一个功能点里不同部分阶段不同时，用 `phText` 写清（例如「P0（完整性基线 P1）」）。PRD 没列、原型自己加的，标 `NA` 并在 `phText` 写「PRD 未列」。

## 三、常见错误（历次复审抓到过的）

| 错误 | 例子 | 怎么避免 |
|---|---|---|
| 把设计目标写成现状 | 「暂停期间每次阻断都会留下带签名的记录」，实际记录还没做 | 目标一律带「按设计」「目标是」；和本卡「现状」对一遍 |
| 白话化时把范围说窄 | 把「执法」换成「超支拦截」，告警、降级也被说成只剩拦截没做 | 换词后逐条对照原文，范围、限定词一个不能丢 |
| 丢掉限定 | 「超过 24 小时一律拒绝」，漏了「Observe 模式的流量除外」 | 原文里的例外、条件原样保留 |
| 同一个词两个意思 | 「连接」一会儿指 Provider，一会儿指 MCP 的连通测试 | 用词约定写进全局说明，全篇统一 |
| 把产品要求写成原型已有 | 「列表能搜索、导出」，原型只画了一行筛选说明 | 写明「按产品要求」，并说清原型画到哪 |
| 现状判档偏高 | 前端表格做了、后端接口返回未实现，被判成已实现 | 判档回源码核对接口实现 |
| 数字不是原型里的 | 自己算的倍数、推测的时间 | 数字只取原型源码里有的，算出来的要写算法 |
| 讲解人提示混进一句话说清 | 「讲 blocked 时说目标行为……」 | talk 只写听众听的那一句 |

## 四、复审清单

复审者只读，只出清单（位置 + 原文 + 问题 + 出处），不改文件；写的人逐条处置后请同一复审者复核改动。除 `docs/PROJECT-GUIDE.md`「落盘前复审」的可读性六条外，本 skill 重点查：

1. **数字与例子**：每个数字、名称都能在原型源码里找到原文。
2. **规则与阶段**：规则说法与 PRD 一致，阶段标注与 PRD 一致，「PRD 与原型不一致」的说法成立。
3. **现状与归属**：档位与代码一致，模块归属与设计、代码一致，「（目标）」没有漏标或误标。
4. **限定**：设计目标没有写成现状，例外条件没有丢，白话化没有改变范围。
5. **用词**：同一个对象全篇只有一个名字；没有残留 PRD 编号、契约编号、文件名。

结构字段（锚点、跳转、阶段、模块键、现状档位）在纯文字改写前后应完全一致，可以用脚本比对两个版本的数据。

## 五、数据目录的 README

数据目录里放一份 `README.md`，写给以后维护的人：生成日期与依据（原型、PRD、设计、代码的版本）；产出文件的位置；原型改版时的四步（见 SKILL.md「原型改版」），命令里写明本 skill 的实际路径；数据格式指向本文件 §一。源文档更新后要同步修订标注。
