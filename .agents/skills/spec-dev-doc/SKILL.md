# 评审面生成

三环流水线的**旁路**，不是必经环：只读 SPEC、不产生三环的输入。

**输入只有一份**：`specs/<模块>.md`（必须已定稿——不存在 → 提示先跑 `/spec-design`，不硬编）。**不读解读、不读 ADR、不收附加取材**——它们已经在 SPEC 定稿时被消化完了。只有一个输入，就没法二次创作。

**产出** = `docs/review/<模块>-v<版本>.html`，自包含单文件，微信/邮件直接发、浏览器直接看。**只收模块范围**：全局全貌住 `docs/ARCHITECTURE.md`，不出全局稿。全程简体中文。

**这是投影，不是汇总**：SPEC 每章有六栏，本稿取前五栏（这章讲什么 / **图** / 为什么这么定 / 要你拍的 / 缺口），第六栏「怎么做」（接口签名、字段清单、失败分支、验证项）**一个字都不取**——它不是折起来，是根本不出现。要看字段的人去读 SPEC。

**图要投影，也要现画——但讲不清就不画。** 评审的人要判断「这么设计对不对」，看得见结构才谈得上判断，所以缺图是缺陷。SPEC 有图的照着投影，SPEC 没画但结构和流向说得清的**现画**。**判据只有一条**：用一句话写出「这张图让读者看懂什么」，写得出就画，写不出说明这张图承担太多或没想清楚——**拆开、换角度，或者干脆不画并把缺图记进缺口栏**，不许硬凑一张看不懂的图。

**读者是要拍板的人**，同时回答三个问题：

| 目的 | 靠什么答 |
|---|---|
| 这些决定定得对不对 | 各章「要你拍的」+ 末尾未决登记；「为什么」提供判断依据 |
| 这份设计够不够开工 | **那个端到端例子能不能从头走通**（主）+ 仪表盘已知缺口（辅） |
| 能不能给人讲明白为什么这么设计 | 一分钟看懂 + 那个例子 + 各章「为什么」 |

「够不够开工」的真正裁判是实现者——他知道缺什么。仪表盘在这里的作用是**让人看到风险敞口**，不是让人判定完备；数缺口只能数出已知缺口。

签字栏、盖章、评审综述、「请评审」框，这些一概没有——评审面不等于评审仪式。

**无草稿文件**：产物本身就是稿——定稿前同版本可反复覆盖（拍板点见流程第 5 步），中途断了重跑同版本接着改；定稿后的文件永不改写。

## 流程

1. **定范围与版本**：参数为空先问模块名。版本号用户指定优先；没指定就自增——`ls docs/review/` 取该模块现有最大版本、末段 +1（v0.5 → v0.6，v0.9 → v0.10，不自动进大版本），该模块首份 = v0.1。发现已有旧版时顺口提醒一句：旧版若含未回流产物的手工补充，可要求「对账 v<N>」。
2. **收料**：只读 `specs/<模块>.md`，**全读**。不读解读、不读 ADR、不收附加取材。SPEC 里缺的东西就是缺的——标「SPEC 中未见」，不去别处找补。**用户明确要求对账旧版**时（如「对账 v0.3」）：加读该版，把「旧版有、SPEC 没有」的实质内容列成清单逐条拍板——回流进 SPEC（走 `/spec-design` 修订轮）或放弃，不静默丢，也不就地补进本稿；不点名就不读旧版。
3. **投影**：按 `reference.md` §一 组织——章节**镜像 SPEC 的章**，SPEC 有几章就有几章，名字沿用，不自己另起一套结构。每章取五栏（含图），「怎么做」栏跳过；「要你拍的」「缺口」两栏 SPEC 里没有就不写，不留「无」占位。SPEC 里标了「待补」「装配时定」的原样带过来，不替它补。
4. **套模板落盘**：从本 skill 目录拷贝 `template.html`，只替换 `<!-- FILL:… -->` 标记的内容区（铁律见 `reference.md` §二），图一律照 `diagram.md` 范式画，写入产物路径。
5. **定稿（拍板点）**：落盘后**必须自检渲染，不是「条件允许」**——① HTML 标签配对与 class 有无定义；② 几何自检（越界 / 节点重叠 / 文字撑框 / 标签压节点）；③ **无头 Chrome 逐图截图目检**，命令与检查清单见 `diagram.md` §八。三步都过了再自检四条硬指标：文字 ≤6 屏（图不计）、单条取舍 ≤3 句、第一层无未解释黑话、**每章该有的图都在**。④ **可读性复审**：换一个模型按 `docs/PROJECT-GUIDE.md`「可读性复审」的五条清单读一遍正文（图与代码除外），命中就改；只许动语言，数字、编号、路径、代码标识符不许改。然后请用户浏览器打开过目。修改意见当场改、同版本覆盖——当场改**只限排版与组织级**；实质新信息（SPEC 没有的事实、决策、数据）不直接进稿，记下来提示回流 SPEC（需求级走 `/spec-interview` 增量轮、设计级走 `/spec-design` 修订轮），回流后重新生成才带上；**用户点头才算定稿**。收尾提示提交这一笔。

## 红线

- **只投影，不创作**：本稿是 SPEC 的投影，内容一个字都不许超出 SPEC。SPEC 没有的信息一律标「SPEC 中未见」。现画的架构图/时序图/状态机只许投影 SPEC 已有信息，画不出的部分就是 SPEC 缺口，如实标出。
- **「怎么做」栏一律不取**：接口签名、字段清单、失败分支、验证项，一个字都不进本稿。发现自己在写这些，说明投影错了——它们的位置在 SPEC。**但图不算实现细节**：架构图、流程时序图、状态机必须进稿。判据是画的是什么——画结构与流向的进稿，画字段与签名的不进。
- **每章的「要你拍的」「缺口」没有就整栏不写**，不留「无」占位。七章都写「无」是噪音，读者会学会跳过它，真有待拍板项时反而看不见。
- **一张图只讲一件事，写不出就别画**（`diagram.md` §零）：下笔前先用一句话写出这张图要让读者看懂什么。写不出 = 不画，把缺图记进缺口栏；画不下 = 拆两张。这条压过「尽量画图」。
- **不要直接调用 `/eli5` 生成图或生成评审面**：它是 6 行提示词、不是渲染器，产出是一个独立完整的网页（自己的标题、排版、配色），没法拆出一张图贴进本模板；而且它的职责是「讲明白」，会补 SPEC 里没有的内容，与「只投影不创作」直接冲突。借的是它的判断标准（大图、少字、一张图只讲一件事），不是它的产物。
- **架构图与流程图用 HTML/CSS 盒子，不手算 SVG 坐标**（`diagram.md` §零点二）：SVG 里位置是人填的数字，填错没人拦；HTML/CSS 里位置是浏览器算的，盒子天生不重叠。**只有泳道时序图用 SVG**，且布线一律正交、禁止斜线——标签牌不得与节点框相交，连线不得穿过节点框。
- **图落盘后必须截图看过**（`diagram.md` §八）：坐标算得对不代表画得对。没截图看过的图不算完成。
- **全文只有一个端到端例子**，放顶部，带一次故障、从头走到尾。不要每章各写一个。
- **限长**：单条取舍 ≤3 句（一章可以有多条取舍，按条计数）；文字部分 ≤6 屏，**图不计入**。超了必然是字段级细节漏进来了，回去删。
- **人话是命门**：第一层出现未解释的黑话算硬伤，重写，不是加个折叠了事。术语与自造比喻第一次出现必须当场半句白话解释；不设集中名词表。**作者看不见自己的黑话**——定稿前必须换一个模型过一遍（`docs/PROJECT-GUIDE.md`「可读性复审」），自审不算。
- **仪表盘须注明只统计已知缺口**：标了「待补」「装配时定」的能数出来，没人想到的洞数不出来。不写这句话就是误导。
- **只报「当前未拍板 N 条」，不报「本版新增 N 条」**：没有可靠的版本 diff 机制，旧版还可能被清理；数状态就行。
- **代码展示两档纪律**：接口签名等从正本**原文照抄**（注明出处、不改一字）；其余一律标「示意」，未定的键名/命名标「装配时定」——不许出现第三种（既不注明出处又写得像真的）。
- **扩展点必须落接缝**：接缝在哪 → 现状 → 将来插什么 → 何时，四样俱全；指不出接缝位置（Port / 接口 / 构造注入点）的不算扩展点，空口承诺不进稿。
- **没有的不硬凑**：没料的小节标「待补」徽标或整节删（侧边导航同步删），不为凑结构编内容。**没有固定章节清单**——章节镜像 SPEC 的章，SPEC 没有的章就不该出现。
- 模板**既有** CSS 与骨架不许改；图专属 style/script 允许新增在内容区，以图 id 限定作用域（时序图/状态机的共享样式模板已内置，见 `diagram.md` §六§七）。样式不满意改的是 skill 里的 `template.html`（母本升级，在 projkit 里改，随刷新分发）。
- 已定稿的旧版本文件永不改写；新一轮 = 新版本号新文件（快照史，和 ADR 追加式同气质）。
- 只出评审面，不回写三环产物——新信息的消化走对应环的增量/修订轮。
