# 章节规则与模板铁律

## 一、投影规则（内容怎么切）

读者是**要拍板的人**（可能没参与设计）——每节都要经得起「零上下文能不能看懂」检验；排版守项目 `docs/PROJECT-GUIDE.md`「文档排版规范」。写法六条：

- **图优先，但「说不清就不画」压过「必须有图」**：能画图的尽量画（架构图 / 流程图 / 状态机，画法照 `diagram.md`），文字只写图表达不了的规则与约束。评审的人要判断「这么设计对不对」，看得见结构才谈得上判断。**但一句话说不出「这张图让读者看懂什么」就不要画**（`diagram.md` §零）：画歪的图、讲不清的图比没有图更糟，读者会照着错的结构去理解。图只许用 SPEC 已有的信息，画不出来的部分就不画——**不画的地方直接跳过，不写「本章没有图」，也不解释为什么没画**。**画完必须按 `diagram.md` §四 渲染检查。**
- **短句**：一句话只说一件事，先结论后原因；不堆嵌套括号与破折号插注，一个长句塞了多层意思就拆成几句。压缩说法要展开成完整因果（「截断合法化」→「先删掉链尾几条，再补写几条把序号填满，删尾就查不出来了」）。
- **大白话（命门）**：术语与自造比喻在第一次出现的地方**必须**当场用半句白话解释（如「fencing（届数围栏，用只增不减的届数把旧写者关在门外）」），没解释过的黑话不许直接用；比喻只在比直说更快让人懂时才用，不为生动硬造；**不设集中名词表**——集中词表读者不看、看了也对不上文。第一层出现未解释黑话算硬伤，重写，不是加折叠了事。
- **重点打标**：结论性内容统一用四种语义徽标标注，让读者一眼分清轻重——`.b.b-pin`「已拍板」（绿，决策已定案）、`.b.b-must`「必须」（红，实现纪律，违反出正确性/安全问题）、`.b.b-later`「后置」（蓝，现在不做、以后做）、`.b.b-test`「实测」（黄，结论经过验证而非推测）。全文只用这一套，不另造颜色与措辞。
- **不设单独决策章**：SPEC 各章「要你拍的」栏就近呈现，末尾只做一张汇总索引表链回各章。
- **实现细节不进正文**：接口签名、字段清单、失败分支、验证项、readiness 细则、落地开关清单，一律留一句指路。**图不在此列**——画结构与流向的图必须进稿，只有画字段与签名的才算实现细节。

### 全篇骨架：整体设计 + 镜像 SPEC 的各章 + 未决登记

**只有头尾两章是固定的**，中间的章镜像 SPEC。

#### 开篇：整体设计（`ch-00`）

章标题就叫「整体设计」，侧边栏第一组同名。**不叫「总览」「概述」「一分钟看懂」**——那些名字只承诺「讲个大概」，这一章要交的是全局设计本身。构成固定六件，顺序不换：

| 位置 | 内容 | 规则 |
|---|---|---|
| 导读 | 一句白话说清这模块干什么 + 一句怎么读 | 零黑话。怎么读那句写清顺序：先看下面两张图各走一遍，再顺着各章的图和「为什么这么定」看，要动代码时才去读 SPEC 的「怎么做」栏 |
| 正常路径几段话 | `<ol class="flowsteps">` | 用文字把主干先过一遍（一般三到五段），给后面两张图打底 |
| 仪表盘 | `<div class="stats">` 四格 | 章数 / 章内待你拍板 / 未决登记条数 / 各章已知缺口；下面 `.cap` 注明「只统计已知缺口」，并说明「设计完不完备看下面那个例子能不能从头走通」 |
| **0.1 全模块结构** | `gen_arch.py` 生成的 SVG（`diagram.md` §一点零） | **交代结构：谁调谁。**这个模块由哪几块组成、谁调谁、哪些本期新建、哪些是外部依赖。**组件和连线都要画全**——SPEC 里有名字的部件（表、后台任务、端口、适配器、外部依赖）各占一格，不合并、不省略；回执、补发、对账追平这类回程一条都不能少，朝上朝下按哪种清楚来。主干每一步的编号标在**线**上（边的第五项），各章沿用同一套号。**宁可多切两层，也不要少画一个部件**。小节标题写实质内容（如「全模块结构」），不写「架构图」 |
| **0.2 整体流程图** | mermaid 时序图（`diagram.md` §二） | 一件事从头到尾怎么走完，**给全流程编号**（`autonumber`，正文用 ①②③ 引用）；0.1 那张架构图沿用这套编号，标出每个部件参与第几步。小节标题带上步数（如「一次发布的十六步」） |
| **0.3 一个走通的例子** | 一段带小标题的正文 | 一个从头走到尾、中间出一次故障的具体例子，用真实的名字和数值。它同时干两件事：讲清整体，以及检验完备性——**例子走不通就是有洞**。全篇只有这一个，不要每章各写一个 |

**两张全局图各占一个带标题的小节**，好挂侧边栏二级导航——0.1 交代结构（谁调谁），0.2 交代时序（一件事怎么走完），互不替代。全篇的步骤编号在 0.2 定义一次，0.1 与各章沿用（`diagram.md` §三）。

#### 中间：章节 = SPEC 章的镜像

**没有固定章节清单。** SPEC 有几章就有几章，名字沿用，顺序沿用。用不上的不出现，不留空章占位——部署、编译器、检测器这类只在相关模块出现。

每章取 SPEC 六栏中的前五栏，`怎么做` 栏跳过：

| 章内小节 | 来自 SPEC | 写法 |
|---|---|---|
| 导读一句 | 这章讲什么 | 1 句，零黑话，用 `<p class="lede">` |
| **图** | 图 | 架构图 / 流程图 / 状态机，照 `diagram.md` 范式画，**紧跟导读句，不单起一个叫「图」的小节**。图上标出本章承担的是全流程第几步。SPEC 有图就投影；SPEC 没画但结构与流向说得清的现画；**一句话说不出这张图讲什么就不画，也不写说明** |
| 为什么这么定 | 为什么这么定 | 按条投影，**每条取舍 ≤3 句**。两条以上用 `<ul>`，每条以粗体一句结论开头再展开（「**必须有回执**。消息被 Kafka 接收只能证明通知发出去了，证明不了某个实例真装上了」）；SPEC 写「照契约，无取舍」的照实写 |
| 要你拍的 | 要你拍的 | `.callout` 就近放，条目带 `.b.b-later`「待拍」；**SPEC 里没有就整栏不写** |
| 缺口 | 缺口 | 只登记 **SPEC 自己标出来的洞**：待补 / 装配时定 / 产物中未见（三档与 SPEC 缺口栏一一对应），用 `.b-g` 徽标；**SPEC 里没有就整栏不写**。本稿自己没做的事（没画图、没展开细节）不算缺口，不登记——「产物中未见」是 SPEC 作者标的洞，「SPEC 中未见」是投影者交代取材，前者要投影、后者一个字都不许写 |

每章最后一句 `.cap` 固定指路：`接口、字段、失败分支见 SPEC《章名》的「怎么做」栏。`

**「无」占位是噪音。** 每章都写「无需裁决」，读者会学会跳过这一栏，真有待拍板项时反而看不见。有才写。

#### 收尾：未决登记（`ch-99`）

全部未拍板事项一张表，固定三列：

| 列 | 写什么 |
|---|---|
| 事项 | 一句话说清没定的是什么 |
| 已留扩展点 | 当前按什么倾向实现、接缝留在哪；确实没有就写「—」 |
| 归属 / 触发 | 卡住谁、什么条件下必须解决 |

导读句写明「每条写当前按什么倾向实现、等什么拍板，不写请评审人回答什么」，并加一句 `实现时不得顺手做掉`。表下 `.cap` 指路分期与验证方案在 SPEC 的哪一章。

### 长度硬指标

**文字部分 ≤6 屏**（图不计入）。超了必然是字段级细节漏进来了，回去删——不是加折叠。长度的硬约束是这条，不是句数；句数只管单条取舍（≤3 句）。

实现细节不进来以后，本稿本来就装得下，**不需要靠折叠压缩**。折叠只用于确实冗长的枚举表（如状态码全表），且折叠里不许藏「为什么」和例子——那两样是读者判断决定对不对的依据，藏起来等于把评审废掉。

### 文件头与侧边栏

**文件头**：标题、一句话说明、元信息栏（范围 / 版本 / 日期 / 状态 / 来源——来源只写一条：`specs/<模块>.md` 及其定稿日期）。**「日期」写本次生成的日期，「来源」写 SPEC 当时的定稿日期，每次覆盖两个都要更新**——下次开工就是靠这两个日期判断这份稿子有没有落后于 SPEC。**无印章、无会签栏、无取材栏**——只有一个输入，不需要登记表。

**侧边栏**：章节与正文一一对应，删了哪章导航同步删。**第一组固定叫「整体设计」，最后一组固定叫「收口」**（放未决登记）；中间各组的组名沿用 SPEC 的自然归组。整体设计章的两张全局图挂二级项 `<a class="sub" href="#锚点">`，其余长章按需加。

**未决问题的口径**：写「当前按什么倾向实现、等什么拍板」，不写「请评审人回答什么」——后者是评审仪式的问法。

## 二、模板使用铁律

- `template.html` 从本 skill 目录**原样拷贝**，只替换 `<!-- FILL:名字 -->` 与 `<!-- /FILL:名字 -->` 之间的内容区（FILL 区注释里写着示例骨架，照抄结构再填内容）；模板既有 CSS、页面骨架、脚本一个字符不动。FILL 区共四处：`title` / `side-brand` / `side-nav` / `body`。
- 正文章节一律 `<section class="sheet" id="ch-NN">`，章头 `<div class="head"><span class="no">NN</span><h1>标题</h1><span class="kind">设计文档</span></div>`，导读 `<div class="lede">`；章内小节 `<h2 id="ch-NN-sM"><span class="h2no">N.M</span>标题</h2>`，被侧边栏二级项链到的小节必须有 id。
- 侧边导航（`FILL:side-nav`）与正文章节一一对应，删了哪节导航同步删；首组「整体设计」、末组「收口」固定，中间分组名沿用 SPEC 的自然归组。
- **画法三选一，见 `diagram.md` §一点零§一§二**：分层架构图用 **`gen_arch.py` 生成 SVG**；单层的模块关系与流程分支用 **HTML/CSS 盒子**（`.dgm` 组件，模板已内置：`.lane` 层 / `.bx` 节点 / `.flow`+`.step` 步骤流；`.bx.new` 新建、`.bx.ext` 外部、`.bx.warn` 异常或需人介入、无修饰 = 已有）；时序图与状态机用 **mermaid**——图源 `.mmd` 经 `render-mermaid.sh` 预渲染成 SVG 贴进 `<figure class="flowviz">`，图下 `<p class="cap">` 写时限与失败语义，图源原文留在 figure 内的 `<script type="text/plain" class="mmd-src">`。图专属 style/script 允许新增在内容区，选择器与逻辑以本图 id 限定作用域。
- **图的三件套**（`diagram.md` §三）：`<figcaption>` 写「图 N　一句话主旨」，步骤多的按段把编号分组带一遍；线型含义写进 `<div class="fig-legend">`（实线一格、虚线一格）；盒子图的图例与结论写进图下的 `<p class="note">`。
- 组件用法：仪表盘 `<div class="stats">` 内放 `.stat`（`<b>` 数字 + `<span>` 说明）；表格包 `<div class="table">`；编号步骤用 `<ol class="flowsteps">`；图注与指路句用 `.cap`；提示块 `.callout`——`.decision` 已决定、`.warn` 易错边界、`.redline` 红线、`.faq` 背景说明。
- 徽标：语义徽标 `.b.b-pin`「已拍板」/ `.b.b-must`「必须」/ `.b.b-later`「后置」/ `.b.b-test`「实测」（用法见 §一「重点打标」）；缺口用 `.b.b-g`（待补 / 装配时定 / 产物中未见，三档与 SPEC 缺口栏一致）。全文只用这一套。**缺口栏不套 `.callout`**——`.callout.warn` 会渲染出「易错边界」标签，与缺口是两回事；缺口条目直接用 `<p>` 加 `.b-g` 徽标。
- 折叠 `<details class="deep">` 只用于确实冗长的枚举表；模板的展开/收起按钮 id 是 `fexp`/`fcol`，**没有折叠块时不要放这两个按钮**（脚本已做空值兜底，不会报错）。
- **文件定位规则（默认覆盖，不自增）**：`ls docs/review/<模块>-v*.html` 有就覆盖版本号最大的那一份、版本号不动——那是当前活跃件，SPEC 改了回来同步走的就是这条路；一份都没有才新建 `<模块>-v0.1.html`。**只有用户显式指定版本号时才另起一份**（末段 +1，v0.5 → v0.6、v0.9 → v0.10；大版本跳变由用户手动指定，不自动进位）：**新建的接任活跃件，旧的就此冻结成快照**，快照不再跟 SPEC 同步。活跃件恒等于版本号最大的那一份，两条规则因此不会打架。
