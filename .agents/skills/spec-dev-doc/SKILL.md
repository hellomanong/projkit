# 开发设计稿生成

三环流水线的**旁路**，不是必经环：只读三环产物、不产生三环的输入。**读者是照着开工的开发者**——顺带也能发给任何人看现状；它不是评审装置：签字栏、盖章、评审综述、「请评审」框、按里程碑给组件标三态，这些一概没有。**输入** = `specs/<模块>.md`（必须已定稿——不存在 → 提示先跑 `/spec-design`，不硬编）+ `docs/prd/解读/<模块>.md` + 该模块 ADR + 附加取材（典型：实现仓库的蓝图/契约文档、里程碑票面，机制见流程第 2 步）；**产出** = `docs/review/<模块>-v<版本>.html`，自包含单文件，微信/邮件直接发、浏览器直接看。**只收模块范围**：全局全貌住 `docs/ARCHITECTURE.md`，不出全局稿。全程简体中文。

**无草稿文件**：产物本身就是稿——定稿前同版本可反复覆盖（拍板点见流程第 5 步），中途断了重跑同版本接着改；定稿后的文件永不改写。

## 流程

1. **定范围与版本**：参数为空先问模块名。版本号用户指定优先；没指定就自增——`ls docs/review/` 取该模块现有最大版本、末段 +1（v0.5 → v0.6，v0.9 → v0.10，不自动进大版本），该模块首份 = v0.1。发现已有旧版时顺口提醒一句：旧版若含未回流产物的手工补充，可要求「对账 v<N>」。
2. **收料**：SPEC 与该模块解读**全读**，该模块 ADR 全读（新盖旧合并要用）；架构导读只读该模块定位。**附加取材**：用户指定的仓库内可重读文件一并全读；该模块已有旧版时先读上一版文件头「取材」栏，登记过的附加取材列出来请用户确认沿用/更换/放弃——取材靠登记传承，不靠每次重新指定；来源不在仓库内的（线上 issue、聊天记录）先落一份进仓库再指过来，**不收口头描述**。**用户明确要求对账旧版**时（如「对账 v0.3」）：加读该版，把「旧版有、产物没有」的实质内容列成清单逐条拍板回流或放弃，不静默丢；不点名就不读旧版。
3. **拼稿**：按 `reference.md` §一 的章节结构组织——总览与全局规则 / 对外接口 / 核心流程（每条一张时序图 + 时限/失败时）/ 子模块章 ×N（统一小节模板）/ 里程碑切片 / 验证方案。ADR 新盖旧合并后的终态结论**内联进对应章节**，不设单独决策章；内容只许来自产物与登记的附加取材，两处都没有的标「产物中未见」或「装配时定」。
4. **套模板落盘**：从本 skill 目录拷贝 `template.html`，只替换 `<!-- FILL:… -->` 标记的内容区（铁律见 `reference.md` §二），图一律照 `diagram.md` 范式画，写入产物路径。
5. **定稿（拍板点）**：落盘后**先自检渲染**——至少做 HTML 标签配对检查，条件允许用无头浏览器整页截图逐段目检（图最容易叠字跑版）；然后请用户浏览器打开过目。修改意见当场改、同版本覆盖——当场改**只限排版与组织级**；实质新信息（产物没有的事实、决策、数据）不直接进稿，记下来提示回流产物（需求级走 `/spec-interview` 增量轮、设计级走 `/spec-design` 修订轮、里程碑级落附加取材文件并登记取材栏），回流后重新生成才带上；**用户点头才算定稿**。收尾提示提交这一笔。

## 红线

- 不替产物编内容：设计稿是产物的汇总与图形化投影，不是二次创作；产物与登记取材都没有的信息一律「产物中未见」。现画的架构图/时序图/状态机只许投影产物已有信息，画不出的部分就是产物缺口，如实标出。
- **代码展示两档纪律**：接口签名等从正本**原文照抄**（注明出处、不改一字）；其余一律标「示意」，未定的键名/命名标「装配时定」——不许出现第三种（既不注明出处又写得像真的）。
- **扩展点必须落接缝**：接缝在哪 → 现状 → 将来插什么 → 何时，四样俱全；指不出接缝位置（Port / 接口 / 构造注入点）的不算扩展点，空口承诺不进稿。
- **没有的不硬凑**：没料的小节标「待补」徽标或整节删（侧边导航同步删），不为凑结构编内容。
- 模板**既有** CSS 与骨架不许改；图专属 style/script 允许新增在内容区，以图 id 限定作用域（时序图/状态机的共享样式模板已内置，见 `diagram.md` §六§七）。样式不满意改的是 skill 里的 `template.html`（母本升级，在 projkit 里改，随刷新分发）。
- 已定稿的旧版本文件永不改写；新一轮 = 新版本号新文件（快照史，和 ADR 追加式同气质）。
- 只出设计稿，不回写三环产物——新信息的消化走对应环的增量/修订轮。
