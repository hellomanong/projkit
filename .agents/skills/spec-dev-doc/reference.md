# 章节规则与模板铁律

## 一、章节规则（内容怎么拼）

读者是**照着开工的开发者**（可能没参与访谈）——每节都要经得起「零上下文能不能看懂」检验；排版守项目 `docs/PROJECT-GUIDE.md`「文档排版规范」。写法六条：

- **图优先**：能画图的一律画图（架构图 / 时序图 / 状态机，画法照 `diagram.md`），文字只写图表达不了的规则与约束。
- **短句**：一句话只说一件事，先结论后原因；不堆嵌套括号与破折号插注，一个长句塞了多层意思就拆成几句。压缩说法要展开成完整因果（「截断合法化」→「先删掉链尾几条，再补写几条把序号填满，删尾就查不出来了」）。
- **大白话（硬规则）**：术语与自造比喻在第一次出现的地方**必须**当场用半句白话解释（如「fencing（届数围栏，用只增不减的届数把旧写者关在门外）」），没解释过的黑话不许直接用；比喻只在比直说更快让人懂时才用，不为生动硬造；**不设集中名词表**——集中词表读者不看、看了也对不上文。
- **重点打标**：结论性内容统一用四种语义徽标标注，让读者一眼分清轻重——`.b.b-pin`「已拍板」（绿，决策已定案）、`.b.b-must`「必须」（红，实现纪律，违反出正确性/安全问题）、`.b.b-later`「后置」（蓝，现在不做、以后做）、`.b.b-test`「实测」（黄，结论经过验证而非推测）。全文只用这一套，不另造颜色与措辞。
- **决策内联**：ADR 新盖旧合并后的终态结论直接写进对应章节（合并细则进模块章、部署决策进总览……），不设单独「决策清单」章；正文不挂 ADR 编号尾注，追溯统一走文件头取材栏。
- **装配琐碎不进正文**：readiness 细则、落地开关清单这类装配级内容留一句「正本见 spec」。

侧边栏三组，章节如下（没料的整节删、导航同步删；章内小节可裁）：

| 组 | 章 | 内容与规则 |
|---|---|---|
| — | 文件头 | 标题、一句话说明、元信息栏（范围 / 版本 / 日期 / 状态 / 部署形态 / 取材——取材列全本稿全部来源，含附加取材路径）、子模块速览卡；**无印章、无会签栏** |
| 架构 | 总览与全局规则 | 定位与边界（是什么 / 不是什么 + 进出关系图）；**整体架构图**——稳态终态，**不带里程碑标注**（哪期做哪块归里程碑章），流向多用交互档；部署与运行形态（单/多副本论证 + 拓扑图）；代码结构与依赖（包依赖方向图 + 依赖纪律）；数据形态；一致性边界；故障语义矩阵（坏了什么 / 怎么办 / 什么绝不许发生）；安全；可观测与运维；全局未决 + 模块未决索引表 |
| 架构 | 对外接口 | 提供的 / 依赖的两张总账表（接口 / 形状 / 错误语义 / 实现在哪章），明细指回模块章；全局约定（错误缺省、版本纪律、契约状态如实标注） |
| 架构 | 核心流程 | 覆盖全部**带时限承诺**的端到端流程与跨模块协作，每条一张泳道时序图 + 图下固定两行「时限」「失败时」；末节「流程反查设计」表——每条流程钉死哪些设计点；不被任何流程走到的组件是冗余候选 |
| 模块 | 子模块章 ×N | 统一小节模板（见下）；章序照请求路径或依赖方向排 |
| 里程碑与验证 | 里程碑切片 | 能力点亮矩阵（子模块 × 里程碑）；**当前里程碑展开完整装配方案**——目标与票面、数据流图、装配清单（组件 / 形态 / 装配说明）、端到端验收（每步带预期结果）、本期明确不做；已完成的压成小卡，未开始的不展开；模块整体范围外清单也收本章 |
| 里程碑与验证 | 验证方案 | 写测试的规矩（表驱动锁细则、fake 纪律、契约不自造、确定性）；压测装置与验收判据；端到端验证序列（每步标最早可验里程碑 + 预期） |

**子模块章统一模板**（小节序固定；确无内容的小节可省）：

1. **摘要卡**（`.startcard`）：代码包路径 + 数量指标（Port 数 / 扩展点数 / 未决数……）+ **实施起点**（当前里程碑先做什么）
2. **负责什么**：负责表 + 「**不负责**」段——边界外的事点名归谁
3. **对外提供的方法**：表带「**前提 / 失败**」两列；关键接口与骨架配代码块（两档纪律见 SKILL.md 红线），代码块前用 `.codecap` 标文件路径与档位（原文照抄 / 示意）
4. **领域对象与状态机**：对象表 + 状态机图（`diagram.md` §七）
5. **依赖**：Port / 接口表——生产 Adapter 背后是什么 + 当前形态（真实现 / fake / 不装）
6. **扩展点**：固定四列表——接缝在哪 / 现状 / 将来插什么 / 何时
7. **怎么验证**：这一模块怎么被测死（含负例与故障注入）
8. **未决**：`.callout.amber` 就近放——「编号 · 标题」+ 倾向方案 + 已否备选；总览章的未决索引表逐条链过来

**未决问题的口径**：开发稿的未决写「当前按什么倾向实现、等什么拍板」，不写「请评审人回答什么」——那是评审装置的问法。

## 二、模板使用铁律

- `template.html` 从本 skill 目录**原样拷贝**，只替换 `<!-- FILL:名字 -->` 与 `<!-- /FILL:名字 -->` 之间的内容区（FILL 区注释里写着示例骨架，照抄结构再填内容）；模板既有 CSS、页面骨架、脚本一个字符不动。FILL 区共八处：`title` / `side-brand` / `side-nav` / `tb-name` / `tb-meta` / `mb`（子模块速览卡；不需要连同外层 `div.mb` 一起删）/ `body` / `footer`。
- 正文章节一律 `<section class="sec" id="sN">`，标题 `<h2><span class="no">§ 0N</span>标题</h2>`，导读 `<p class="lede">`；小节 `<h3><span class="h3no">N.M</span>标题</h3>`，被侧边栏二级项链到的小节加 id。
- 侧边导航（`FILL:side-nav`）三组（架构 / 模块 / 里程碑与验证）与正文章节一一对应，删了哪节导航同步删；长章（总览、核心流程）可加二级项 `<a class="sub" href="#锚点">`。
- 图一律**内联 SVG** 照 `diagram.md` 范式：架构图结构五件套；时序图 svg 挂 `class="seqv"`、状态机挂 `class="stm"`——两者的共享样式模板已内置，图内只需要自己的 marker defs；图专属 style/script 允许新增在内容区，选择器与逻辑以本图 id 限定作用域。
- 组件用法：模块摘要卡 `.startcard`；编号条目 `.prin`；表格包 `<div class="twrap">`；状态徽标（白底）`.b`——`b-c` 标当前里程碑（如「当前 · M1」）、`b-g` 标「待补」、`b-k`/`b-r` 备用；语义徽标（软底填色）`b-pin`「已拍板」/ `b-must`「必须」/ `b-later`「后置」/ `b-test`「实测」——用法见 §一「重点打标」；提示块 `.callout`——amber = 未决、warn = 警示红线、blue = 背景说明；代码块 `.codecap` 说明行 + `<pre><code>`。
- 版本自增规则：`ls docs/review/<模块>-v*.html` 取最大版本，末段 +1（v0.5 → v0.6，v0.9 → v0.10）；大版本跳变由用户手动指定，不自动进位。
