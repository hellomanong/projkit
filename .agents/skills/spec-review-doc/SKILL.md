# 评审稿生成

三环流水线的**旁路**，不是必经环：只读三环产物、不产生三环的输入。**输入** = 该范围现有产物——`docs/prd/解读/<范围>.md` 与该范围 ADR 必取，`specs/<范围>.md`、`docs/ARCHITECTURE.md` 存在就纳入；**产出** = `docs/review/<范围>-v<版本>.html`，自包含单文件，微信/邮件直接发、浏览器直接看。评审意见的回流不归本 skill 管——由用户消化后按需跑 `/spec-interview` 增量轮。全程简体中文。

**无草稿文件**：产物本身就是稿——定稿前同版本可反复覆盖（拍板点见流程第 5 步），中途断了重跑同版本接着改；定稿后的文件永不改写。

## 流程

1. **定范围与版本**：参数为空先问范围（全局或模块名）。版本号用户指定优先；没指定就自增——`ls docs/review/` 取该范围现有最大版本、末段 +1（v0.5 → v0.6，v0.9 → v0.10，不自动进大版本；想要 v1.0 手动指定），该范围首份 = v0.1。
2. **收料**：该范围 ADR **全读**（合并要用）；解读、SPEC、架构导读先扫「## 块名」标题定位、只读相关块。全局范围读全局解读 + 全局 ADR + ARCHITECTURE.md；模块范围读该模块的解读、ADR、SPEC（其模块图——稳态全貌 + 本轮标记——必须收进评审稿）及架构导读中该模块的定位。该范围一份产物都没有 → 提示先跑 `/spec-interview <范围>`，不硬编。
3. **拼稿**：按 `reference.md` §一 的章节规则组织内容——ADR 新盖旧合并成「当前有效决策」终态清单、各节标成熟度、未决问题逐条配「请评审人回答什么」。**内容只许来自产物文件**，产物没写的标「产物中未见」。
4. **套模板落盘**：从本 skill 目录拷贝 `template.html`，只替换 `<!-- FILL:… -->` 标记的内容区（铁律见 `reference.md` §二），写入产物路径。
5. **定稿（拍板点）**：提示用户用浏览器打开检查——HTML 得渲染着看，所以拍板点在落盘后；修改意见当场改、同版本覆盖，**用户点头才算定稿**。收尾提示提交这一笔。

## 红线

- 不替产物编内容：评审稿是汇总视图，不是二次创作；解读/ADR/SPEC 没有的信息一律「产物中未见」。
- 模板 CSS 与骨架不许改——排版稳定性全靠模板写死；样式不满意改的是 skill 里的 `template.html`（母本升级，在 projkit 里改，随刷新分发）。
- 已定稿的旧版本文件永不改写；新一轮评审 = 新版本号新文件（快照史，和 ADR 追加式同气质）。
- 只出评审稿，不回写三环产物——评审意见的消化是 `/spec-interview` 增量轮的事。
