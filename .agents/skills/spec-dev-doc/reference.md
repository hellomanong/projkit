# 章节规则与模板铁律

## 一、投影规则（内容怎么切）

读者是**要拍板的人**（可能没参与设计）——每节都要经得起「零上下文能不能看懂」检验；排版守项目 `docs/PROJECT-GUIDE.md`「文档排版规范」。写法五条：

- **图优先**：能画图的尽量画，文字只写图表达不了的规则与约束。画不画、怎么交给 diagram-design、贴入前查什么，全在 `SKILL.md` 流程第 4、6 步与红线，这里不重复。
- **短句**：一句话只说一件事，先结论后原因；不堆嵌套括号与破折号插注，一个长句塞了多层意思就拆成几句。压缩说法要展开成完整因果（「截断合法化」→「先删掉链尾几条，再补写几条把序号填满，删尾就查不出来了」）。
- **大白话（命门）**：术语与自造比喻在第一次出现的地方**必须**当场用半句白话解释（如「fencing（届数围栏，用只增不减的届数把旧写者关在门外）」），没解释过的黑话不许直接用；比喻只在比直说更快让人懂时才用，不为生动硬造；**不设集中名词表**——集中词表读者不看、看了也对不上文。
- **重点打标**：结论性内容统一用四种语义徽标标注，让读者一眼分清轻重——`.b.b-pin`「已拍板」（绿，决策已定案）、`.b.b-must`「必须」（红，实现纪律，违反出正确性/安全问题）、`.b.b-later`「后置」（蓝，现在不做、以后做）、`.b.b-test`「实测」（黄，结论经过验证而非推测——只给 SPEC 里验证状态写「已验证」的结论挂，SPEC 写「未验证」的不许挂）。全文只用这一套，不另造颜色与措辞。
- **决策就近呈现**：不设单独的决策章——已定的理由住各章「为什么这么设计」、待拍的住各章「要你拍的」；末尾两张登记表是 SPEC 现成登记的投影，不重复论证（见「收尾」）。

### 全篇骨架：整体设计 + 镜像 SPEC 的各章 + 已决登记 + 未决登记

**固定的只有三章**——开篇 `ch-00` 整体设计、收尾 `ch-98` 已决登记与 `ch-99` 未决登记。中间的章镜像 SPEC，SPEC 有几章就有几章、叫什么就叫什么。

#### 开篇：整体设计（`ch-00`）

章标题就叫「整体设计」，侧边栏第一组同名。构成六件，顺序不换；非流水线模块可省 0.2，省了就导读改写「先看下面这张图」，0.3 照 0.1 的结构走一遍（挑一个部件的一次调用当例子，仍带一次故障）：

| 位置 | 内容 | 规则 |
|---|---|---|
| 导读 | 一句白话说清这模块干什么 + 一句怎么读 | 零黑话。怎么读那句写清顺序：先看下面两张图各走一遍，再顺着各章的图和「为什么这么设计」看，要动代码时才去读 SPEC 的「怎么做」栏 |
| 正常路径几段话 | `<ol class="flowsteps">` | 用文字把主干先过一遍（一般三到五段），给后面两张图打底 |
| 仪表盘 | `<div class="stats">` 四格 | 章数 / 已决登记条数（98 章）/ 未决登记条数（99 章）/ 各章已知缺口；下面 `.cap` 注明「只统计已知缺口」，并说明「设计完不完备看下面那个例子能不能从头走通」 |
| **0.1 全模块结构** | 图 | 交代结构：由哪些部件组成、外面有谁、跟外面怎么来往、哪些本期新建。小节标题写实质内容（如「全模块结构」） |
| **0.2 一件事怎么走完** | 图 | 一件事从头到尾怎么走完，异常分支也喂给它、拆不拆它定。小节标题说清这张图讲什么（如「一次发布怎么走完」） |
| **0.3 一个走通的例子** | 一段带小标题的正文 | 一个从头走到尾、中间出一次故障的具体例子，用真实的名字和数值。它同时干两件事：讲清整体，以及检验完备性——**例子走不通就是有洞** |

#### 中间：章节 = SPEC 章的镜像

章名、顺序沿用 SPEC；不留空章占位。

每章取 SPEC 六栏中的前五栏，`怎么做` 栏跳过：

| 章内小节 | 来自 SPEC | 写法 |
|---|---|---|
| 导读一句 | 这章讲什么 | 1 句，零黑话，用 `<p class="lede">` |
| 图 | 图 | 紧跟导读句。SPEC 有图就投影；SPEC 没画但结构、顺序或状态说得清的现画 |
| 为什么这么设计 | 为什么这么定 | **小节名改叫「为什么这么设计」**，SPEC 那边的栏名不动。按条投影，长短照 SPEC、不另行压缩；每条末尾的验证状态原样带过来——`已验证：…` 的给结论挂 `.b.b-test`「实测」徽标，`未验证：…` 的照原文写出来，不挂徽标、也不删。两条以上用 `<ul>`，每条以粗体一句结论开头再展开（「**必须有回执**。消息被 Kafka 接收只能证明通知发出去了，证明不了某个实例真装上了」）；SPEC 写「照契约，无取舍」的照实写 |
| 要你拍的 | 要你拍的 | `.callout` 就近放，不挂徽标（`.b-later` 只表示后置）；**SPEC 里没有就整栏不写** |
| 缺口 | 缺口 | 只登记 **SPEC 自己标出来的洞**：待补 / 装配时定 / 产物中未见（三档与 SPEC 缺口栏一一对应），用 `.b-g` 徽标；**SPEC 里没有就整栏不写**。「产物中未见」是 SPEC 作者标的洞，要投影；「SPEC 中未见」是投影者交代取材，一个字都不许写 |

每章最后一句 `.cap` 固定指路：`接口、字段、失败分支见 SPEC《章名》的「怎么做」栏。`

#### 收尾：已决登记（`ch-98`）+ 未决登记（`ch-99`）

两章固定，先已决后未决——读者先扫一遍已经定了的有没有异议，再落到还等他拍的。**两张都是 SPEC「决策与未决登记」章的投影**：那一章固定装「决策登记」（问题 → 选择 → 理由三件套，加验证状态）和「未拍板清单」（事项 + 已留扩展点 + 归属/触发），逐条搬过来、一条一行，再加一列回链到本稿相关的那一节；不从各章正文自己攒，也不重复各章的论证。

**98 已决登记**：SPEC 决策登记的投影，固定五列：

| 列 | 写什么 |
|---|---|
| 问题 | 当时在选什么，照 SPEC |
| 选择 | 定了什么，照 SPEC |
| 理由 | 照 SPEC，含被否项及否因；≤1 句装不下的截到句号为止，完整版在 SPEC |
| 验证 | 照 SPEC：`已验证：怎么验的` 或 `未验证：据什么推的`；SPEC 这一格空着就原样留空，不替它补、不计入缺口，记下来提示回流 `/spec-design` 修订轮 |
| 定在哪 | 回链本稿相关的节：`<a href="#ch-03-s1">见 3.1</a>`；跨章的链整体设计章。链接必须点得开 |

导读句写明「这些是已经定下的，扫一遍看有没有你不认可的；每条的完整取舍在它所属那一章」。整章都是已拍板的，行内**不挂 `.b-pin` 徽标**——满屏徽标等于没有徽标。

**99 未决登记**：SPEC 未拍板清单的投影，固定三列；缺口（待补 / 装配时定）不进这张表，它们住各章缺口栏和仪表盘第四格：

| 列 | 写什么 |
|---|---|
| 事项 | 一句话说清没定的是什么 |
| 已留扩展点 | 当前按什么倾向实现、接缝留在哪；确实没有就写「—」 |
| 归属 / 触发 | 卡住谁、什么条件下必须解决 |

导读句写明「每条写当前按什么倾向实现、等什么拍板，不写请评审人回答什么」（后者是评审仪式的问法），并加一句 `实现时不得顺手做掉`。表下 `.cap` 指路分期与验证方案在 SPEC 的哪一章。

**两章都可能没料**：SPEC 没有「决策与未决登记」章或决策登记是空的，说明 SPEC 没定稿到位，提示回 `/spec-design` 补——不是把这章删了。未拍板清单是空的，就照实写「当前无未决事项」，**这是全篇唯一允许的「无」占位**，因为「没有未决」本身是个要人知道的结论。

### 文件头与侧边栏

**文件头**：标题、一句话说明、元信息栏（范围 / 版本 / 日期 / 状态 / 来源——来源只写一条：`specs/<模块>.md` 及其定稿日期）。**「日期」写本次生成的日期，「来源」写 SPEC 当时的定稿日期，每次覆盖两个都要更新**——下次开工就是靠这两个日期判断这份稿子有没有落后于 SPEC。无印章、无会签栏、无取材栏。

**侧边栏**：章节与正文一一对应，删了哪章导航同步删。**第一组固定叫「整体设计」，最后一组固定叫「收口」**（放 98 已决登记、99 未决登记两章）；中间各组的组名沿用 SPEC 的自然归组。整体设计章的 0.1 / 0.2 / 0.3 挂二级项 `<a class="sub" href="#锚点">`，其余长章按需加。

## 二、模板使用铁律

- `template.html` 从本 skill 目录**原样拷贝**，只替换 `<!-- FILL:名字 -->` 与 `<!-- /FILL:名字 -->` 之间的内容区（FILL 区注释里写着示例骨架，照抄结构再填内容）；模板既有 CSS、页面骨架、脚本一个字符不动。FILL 区共四处：`title` / `side-brand` / `side-nav` / `body`。
- 正文章节一律 `<section class="sheet" id="ch-NN">`，章头 `<div class="head"><span class="no">NN</span><h1>标题</h1><span class="kind">设计文档</span></div>`，导读 `<div class="lede">`；章内小节 `<h2 id="ch-NN-sM"><span class="h2no">N.M</span>标题</h2>`，被侧边栏二级项链到的小节必须有 id。
- 侧边导航（`FILL:side-nav`）与正文章节一一对应，删了哪节导航同步删；首组「整体设计」（一章）、末组「收口」（98 已决登记 + 99 未决登记两条）固定，中间分组名沿用 SPEC 的自然归组。
- **图一律 `<figure class="flowviz">`**：里面依次是 diagram-design 导出的 `<svg>`（已删 `@import`）、`<figcaption>`（「图 N　一句话主旨」）、`<p class="cap">`（时序/状态图写 `时限：…` / `失败时：…`，有回调的流程图再逐行列接力参数，行间用 `<br>`；结构图写它与别的图的分工）。`.flowviz` 只管留白与横向滚动，不给图加边框底色，图的外观全由 SVG 自己决定。
- 组件用法：仪表盘 `<div class="stats">` 内放 `.stat`（`<b>` 数字 + `<span>` 说明）；表格包 `<div class="table">`；编号步骤用 `<ol class="flowsteps">`；图注与指路句用 `.cap`；提示块 `.callout`——不带修饰类用于「要你拍的」，`.warn` 易错边界、`.redline` 红线、`.faq` 背景说明。
- 徽标：语义徽标 `.b.b-pin`「已拍板」/ `.b.b-must`「必须」/ `.b.b-later`「后置」/ `.b.b-test`「实测」（用法见 §一「重点打标」；`.b-pin` 是行内强调，不是 98 的登记来源）；缺口用 `.b.b-g`（待补 / 装配时定 / 产物中未见）。全文只用这一套。**缺口栏不套 `.callout`**——`.callout.warn` 会渲染出「易错边界」标签，与缺口是两回事；缺口条目直接用 `<p>` 加 `.b-g` 徽标。
