# 章节规则与模板铁律

## 一、投影规则（内容怎么切）

读者是**要拍板的人**（可能没参与设计）——每节都要经得起「零上下文能不能看懂」检验；排版守项目 `docs/PROJECT-GUIDE.md`「文档排版规范」。写法六条：

- **图优先，但「说不清就不画」压过「必须有图」**：能画图的尽量画（架构图 / 流程图 / 状态机，画法照 `diagram.md`），文字只写图表达不了的规则与约束。评审的人要判断「这么设计对不对」，看得见结构才谈得上判断——所以缺图是缺陷，要在缺口栏如实标出。**但一句话说不出「这张图让读者看懂什么」就不要画**（`diagram.md` §零）：画歪的图、讲不清的图比没有图更糟，读者会照着错的结构去理解。图只许投影 SPEC 已有信息，画不出的部分就是 SPEC 缺口。**画完必须按 `diagram.md` §八 渲染检查。**
- **短句**：一句话只说一件事，先结论后原因；不堆嵌套括号与破折号插注，一个长句塞了多层意思就拆成几句。压缩说法要展开成完整因果（「截断合法化」→「先删掉链尾几条，再补写几条把序号填满，删尾就查不出来了」）。
- **大白话（命门）**：术语与自造比喻在第一次出现的地方**必须**当场用半句白话解释（如「fencing（届数围栏，用只增不减的届数把旧写者关在门外）」），没解释过的黑话不许直接用；比喻只在比直说更快让人懂时才用，不为生动硬造；**不设集中名词表**——集中词表读者不看、看了也对不上文。第一层出现未解释黑话算硬伤，重写，不是加折叠了事。
- **重点打标**：结论性内容统一用四种语义徽标标注，让读者一眼分清轻重——`.b.b-pin`「已拍板」（绿，决策已定案）、`.b.b-must`「必须」（红，实现纪律，违反出正确性/安全问题）、`.b.b-later`「后置」（蓝，现在不做、以后做）、`.b.b-test`「实测」（黄，结论经过验证而非推测）。全文只用这一套，不另造颜色与措辞。
- **不设单独决策章**：SPEC 各章「要你拍的」栏就近呈现，末尾只做一张汇总索引表链回各章。
- **实现细节不进正文**：接口签名、字段清单、失败分支、验证项、readiness 细则、落地开关清单，一律留一句「细节见 SPEC《章名》」。**图不在此列**——画结构与流向的图必须进稿，只有画字段与签名的才算实现细节。

### 章节 = SPEC 章的镜像

**没有固定章节清单。** SPEC 有几章就有几章，名字沿用，顺序沿用。用不上的不出现，不留空章占位——部署、编译器、检测器这类只在相关模块出现。

每章取 SPEC 六栏中的前五栏，`怎么做` 栏跳过：

| 章内小节 | 来自 SPEC | 写法 |
|---|---|---|
| 导读一句 | 这章讲什么 | 1 句，零黑话，用 `<p class="lede">` |
| **图** | 图 | 架构图 / 流程图 / 状态机，照 `diagram.md` 范式画。SPEC 有图就投影；SPEC 没画但结构与流向说得清的现画；**一句话说不出这张图讲什么就不画**，缺图记进缺口栏 |
| 为什么这么定 | 为什么这么定 | 按条投影，**每条取舍 ≤3 句**；SPEC 写「照契约，无取舍」的照实写 |
| 要你拍的 | 要你拍的 | `.callout` 就近放，条目带 `.b.b-later`「待拍」；**SPEC 里没有就整栏不写** |
| 缺口 | 缺口 | 待补 / 装配时定 / SPEC 中未见，用 `.b-g` 徽标；**SPEC 里没有就整栏不写** |

**「无」占位是噪音。** 每章都写「无需裁决」，读者会学会跳过这一栏，真有待拍板项时反而看不见。有才写。

### 全篇固定三件

| 位置 | 内容 | 规则 |
|---|---|---|
| 顶部 | **一分钟看懂** | 一句白话说清这模块干什么，零黑话 |
| 顶部 | **仪表盘** | 规模计数 + 已知缺口计数 + **当前未拍板 N 条**（点开跳各章）；须注明「只统计已知缺口」；不报「本版新增」 |
| 正文最前 | **一个端到端例子** | **全文唯一一个**，带一次故障、从头走到尾。它同时干两件事：讲清整体，以及检验完备性——例子走不通就是有洞 |
| 末尾 | 未决登记 | 全部未拍板项汇总，每条注明卡住谁；写「当前按什么倾向实现、等什么拍板」，不写「请评审人回答什么」 |

### 长度硬指标

**文字部分 ≤6 屏**（图不计入）。超了必然是字段级细节漏进来了，回去删——不是加折叠。长度的硬约束是这条，不是句数；句数只管单条取舍（≤3 句）。

实现细节不进来以后，本稿本来就装得下，**不需要靠折叠压缩**。折叠只用于确实冗长的枚举表（如状态码全表），且折叠里不许藏「为什么」和例子——那两样是读者判断决定对不对的依据，藏起来等于把评审废掉。

### 文件头与侧边栏

**文件头**：标题、一句话说明、元信息栏（范围 / 版本 / 日期 / 状态 / 来源——来源只写一条：`specs/<模块>.md` 及其定稿日期）。**无印章、无会签栏、无取材栏**——只有一个输入，不需要登记表。

**侧边栏**：章节与正文一一对应，删了哪章导航同步删。章数多时按 SPEC 的自然归组分组（组名沿用 SPEC，没有固定组名）；长章可加二级项 `<a class="sub" href="#锚点">`。

**未决问题的口径**：写「当前按什么倾向实现、等什么拍板」，不写「请评审人回答什么」——后者是评审仪式的问法。

## 二、模板使用铁律

- `template.html` 从本 skill 目录**原样拷贝**，只替换 `<!-- FILL:名字 -->` 与 `<!-- /FILL:名字 -->` 之间的内容区（FILL 区注释里写着示例骨架，照抄结构再填内容）；模板既有 CSS、页面骨架、脚本一个字符不动。FILL 区共四处：`title` / `side-brand` / `side-nav` / `body`。
- 正文章节一律 `<section class="sheet" id="ch-NN">`，章头 `<div class="head"><span class="no">NN</span><h1>标题</h1><span class="kind">评审面</span></div>`，导读 `<div class="lede">`；章内小节 `<h2 id="ch-NN-sM"><span class="h2no">N.M</span>标题</h2>`，被侧边栏二级项链到的小节必须有 id。
- 侧边导航（`FILL:side-nav`）与正文章节一一对应，删了哪节导航同步删；**分组名沿用 SPEC 的自然归组，没有固定组名**；长章可加二级项 `<a class="sub" href="#锚点">`。
- **画法二选一，见 `diagram.md` §零点二**：架构图与流程图用 **HTML/CSS 盒子**（`.dgm` 组件，模板已内置：`.lane` 层 / `.bx` 节点 / `.flow`+`.step` 步骤流；`.bx.new` 新建、`.bx.ext` 外部、无修饰 = 已有）；泳道时序图用**内联 SVG**（`class="seqv"`，共享样式已内置，图内只需自己的 marker defs）；状态机二选一。图专属 style/script 允许新增在内容区，选择器与逻辑以本图 id 限定作用域。
- 组件用法：仪表盘 `<div class="stats">` 内放 `.stat`（`<b>` 数字 + `<span>` 说明）；表格包 `<div class="table">`；图注与「细节见 SPEC」指路用 `.cap`；提示块 `.callout`——`.decision` 已决定、`.warn` 易错边界、`.redline` 红线、`.faq` 背景说明。
- 徽标：语义徽标 `.b.b-pin`「已拍板」/ `.b.b-must`「必须」/ `.b.b-later`「后置」/ `.b.b-test`「实测」（用法见 §一「重点打标」）；缺口用 `.b.b-g`（待补 / 装配时定 / SPEC 中未见）。全文只用这一套。
- 折叠 `<details class="deep">` 只用于确实冗长的枚举表；模板的展开/收起按钮 id 是 `fexp`/`fcol`，**没有折叠块时不要放这两个按钮**（脚本已做空值兜底，不会报错）。
- 版本自增规则：`ls docs/review/<模块>-v*.html` 取最大版本，末段 +1（v0.5 → v0.6，v0.9 → v0.10）；大版本跳变由用户手动指定，不自动进位。
