# 评审稿生成

三环流水线的**旁路**，不是必经环：只读三环产物、不产生三环的输入。**输入** = 该范围现有产物——`docs/prd/解读/<范围>.md` 与该范围 ADR 必取，`specs/<范围>.md`、`docs/ARCHITECTURE.md` 存在就纳入；**产出** = `docs/review/<范围>-v<版本>.html`，自包含单文件，微信/邮件直接发、浏览器直接看。评审意见的回流不归本 skill 管——由用户消化后按需跑 `/spec-interview` 增量轮。全程简体中文。

**无草稿文件**：产物本身就是稿——定稿前同版本可反复覆盖（拍板点见流程第 5 步），中途断了重跑同版本接着改；定稿后的文件永不改写。

## 流程

1. **定范围与版本**：参数为空先问范围（全局或模块名）。版本号用户指定优先；没指定就自增——`ls docs/review/` 取该范围现有最大版本、末段 +1（v0.5 → v0.6，v0.9 → v0.10，不自动进大版本；想要 v1.0 手动指定），该范围首份 = v0.1。发现已有旧版时顺口提醒一句：旧版若含未回流产物的手工补充，可要求「对账 v<N>」（做法见第 2 步）。
2. **收料**：该范围 ADR **全读**（合并要用）；解读、SPEC、架构导读先扫「## 块名」标题定位、只读相关块——**模块范围例外：该模块解读全读**（稳态架构图要按它现画）。全局范围读全局解读 + 全局 ADR + ARCHITECTURE.md；模块范围读该模块的解读、ADR、SPEC 及架构导读中该模块的定位。该范围一份产物都没有 → 提示先跑 `/spec-interview <范围>`，不硬编。**用户明确要求对账旧版**时（如「对账 v0.3」）：加读该版评审稿，拼稿后把「旧版有、产物没有」的实质内容列成对账清单——逐条由用户拍板回流产物（按需 `/spec-interview` 增量轮）还是放弃，不静默丢；不点名对账就不读旧版（每版都从产物重新生成，评审稿只是快照不是事实来源）。
3. **拼稿**：按 `reference.md` §一 的章节规则组织内容——ADR 新盖旧合并成「当前有效决策」终态清单、各节标成熟度、未决问题逐条配「请评审人回答什么」；模块范围稿在「设计方案」节**现画模块稳态架构图**（取材与内容规范见 `reference.md` §一，画法一律照 `diagram.md` 范式）。**内容只许来自产物文件**，产物没写的标「产物中未见」。
4. **套模板落盘**：从本 skill 目录拷贝 `template.html`，只替换 `<!-- FILL:… -->` 标记的内容区（铁律见 `reference.md` §二），写入产物路径。
5. **定稿（拍板点）**：提示用户用浏览器打开检查——HTML 得渲染着看，所以拍板点在落盘后；修改意见当场改、同版本覆盖——但当场改**只限排版与组织级**；实质新信息（产物里没有的事实、决策、数据）不直接进稿，记下来提示回流产物（按需 `/spec-interview` 增量轮）、回流后重新生成才带上——否则下版重生成时会静默丢失；**用户点头才算定稿**。收尾提示提交这一笔。

## 红线

- 不替产物编内容：评审稿是汇总视图，不是二次创作；解读/ADR/SPEC 没有的信息一律「产物中未见」。**现画稳态架构图不算破例**——它和 ADR 合并成终态清单同一性质，是产物信息的图形化投影；但只许投影产物已有信息，不得画出产物未记载的组件或数据流，画不出的部分就是产物缺口，标「产物中未见」请评审人补。
- 模板**既有** CSS 与骨架不许改——排版稳定性全靠模板写死；架构图一律内联 SVG，图专属 CSS/JS 允许新增在内容区（以图 id 限定作用域，规范见 `reference.md` §二）；样式不满意改的是 skill 里的 `template.html`（母本升级，在 projkit 里改，随刷新分发）。
- 已定稿的旧版本文件永不改写；新一轮评审 = 新版本号新文件（快照史，和 ADR 追加式同气质）。
- 只出评审稿，不回写三环产物——评审意见的消化是 `/spec-interview` 增量轮的事。
