# spec-proto-tour 示例

以下取自一份真实的讲解标注（AGS 原型 · Provider 与模型，17 屏、152 个功能点），「改前」都是被用户或复审打回过的写法。

## 一、功能解释：讲解不是翻译

**改前**（只把界面名词翻了一遍）：

> 四个连接参数：单次超时 30 s、重试 2 次、冷却 60 s、被动健康（出错成串时触发冷却）。右上角可以一键恢复出厂值。下方灰字再次强调：fallback 和负载均衡是调度，不在这里。

**改后**（每项讲清意思和后果，再用原型里的例子把四项串起来）：

```js
{
  t: 'Reliability：供应商出错时，这个 Provider 怎么自保', ph: 'P0', a: { text: 'connection semantics' },
  what: '这一节的四项，规定一个 Provider 在出错时怎么处理，例如网络抖动、供应商限流返回 429、某个区域整体变慢。\n\n' +
    '**Timeout 30 s（超时）**：发出一次请求后最多等 30 秒，还没拿到回复就算这次失败。设得太短，会把本来就要想很久的长回答误判为失败；设得太长，agent 会一直干等。\n\n' +
    '**Retries 2（重试）**：一次失败后，对同一个 Provider 最多再试 2 次，用来消化偶发错误。代价是每次重试都要多等一段时间，也可能多付一次调用的钱。\n\n' +
    '**Cooldown 60 s（冷却）**：一个 Provider 短时间内接连失败，就先把它「摘下来」60 秒，之后再放请求试探，正常了就恢复。\n\n' +
    '**Passive health（被动健康）**：不专门发探测请求，只看真实调用的结果：错误或超时成串出现，就判定它不健康，并触发冷却。\n\n' +
    '**四项怎么配合**：原型里 DeepSeek 自托管集群接连超时 3 次，被动健康判定它不健康，让它冷却 60 秒，这一行随即显示 cooldown。冷却期间，economy 模型组按成员顺序把请求交给下一个成员 gemini-3.5-flash，这一步叫 fallback，归 Smart Routing 管。gemini 的单价贵好几倍，多付的钱在 Cost Control 里记作 Reliability premium。',
  mods: [['gc-gw', '保存超时、重试、冷却参数'], ['litellm', '（目标）执行这些参数']],
  st: ['part', '四个值只保存在 GC，既不下发也不执行，所以现在修改它们不会改变任何实际调用'],
  talk: '超时管「等多久」，重试管「再试几次」，冷却管「坏了先歇多久」，被动健康管「怎么判断坏了」；坏了之后换哪个模型，是 Smart Routing 的事。'
}
```

同一个 DeepSeek 冷却的例子，还出现在 Health 列、模型组的成员健康、成本页的 Reliability premium 几张卡里，讲的时候前后能接上。

## 二、功能解释：去掉规格腔和内部词

**改前**（照搬需求文档的说法）：

> 「Opened from」只说明从哪个入口进来，入口只改变预选的上下文和返回路径，保存时落下的审计动作完全相同。

**改后**：

> 改一个模型的准入，可以从三个地方进来：Models 列表、模型详情页、Gateway 的 Provider 抽屉。不管从哪里进来，打开的都是这同一个抽屉，能改的内容和保存后的效果完全一样。唯一的区别是顶部的「Opened from」会写明你是从哪里来的，改完点返回，会回到原来的页面。

## 三、后端怎么写：模块标签 + 现状，不写技术细节

**改前**（接口、契约、源码混在一起，听众读不动）：

> 接口：POST /api/v1/gateway/providers/{id}/credential（rotateGatewayProviderCredential）
> 设计四步：GC 存新版本与 pending_credential_ref -> GCS 探测 -> 切换 revision -> 确认后擦除旧行
> 现状：GC 在一个事务里直接换版本，没有 pending 中间态和探测

## 四、一句话说清：给听众的话，不是给讲解人的提示

| 不要 | 要 |
|---|---|
| 讲 blocked 时说目标行为：确认影响范围后，30 秒内全网拒绝。 | blocked 就是这个模型谁都不能再调：按设计，确认影响范围后 30 秒内全网生效，每次拒绝都留下记录。 |
| 这张表值得在讲解开头就放出来，后面每一页都是它的展开。 | 每个字段只有一个地方能改：准入在模型记录，连接在 Gateway，组和路由在 Smart Routing，预算和价格在 Cost Control。 |
