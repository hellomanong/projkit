# 原型讲解标注

三环流水线的**旁路**：不产生三环的输入，也不改 PRD 与原型。读者是要把这批页面讲给别人听、自己还没吃透的人。全程简体中文。

**输入**：原型 HTML（按 `docs/解读/README.md` 登记表找；现场给路径也行）+ PRD + 设计文档与代码（用来写「归属模块」「现状」；项目还没有后端时这两栏可以整栏不写）。
**产出**：`docs/解读/<主题>-原型讲解.html`（自包含，浏览器直接打开）+ 同名数据目录 `docs/解读/<主题>-原型讲解/`（`data-*.js` 与 `README.md`）。原型原文件不动。

页面上的能力由 `assets/engine.js` 提供，不用重写：编号圆点跟随页面元素；面板可拖动、缩放、折叠、隐藏；打开抽屉时面板自动停到左侧；目录页一键「带我去」自动点击原型导航；「逐页自检」自动走完全部屏幕，列出没落到元素上的圆点。

## 流程

1. **定范围**：参数为空先问主题。跑 `python3 <skill>/assets/unpack.py <原型> <临时目录>`，拿到全部屏幕与抽屉（`data-screen-label`）；列出与主题相关的屏幕，连同建议纳入与排除的理由给用户确认。原型没有 `data-screen-label` 时，先说明需要扩展引擎的屏幕识别，不硬做。数据目录已存在时，按下面「原型改版」一节走，不从头写。
2. **读原型**：逐屏读页面标记与数据（打包原型读 `markup.html` 与 `app.js`），记下每个功能点的界面文字、交互、原型里现成的数字和例子。锚点与例子都从这里取。
3. **查依据**：PRD 里的规则、阶段、与原型的差异；设计与代码里的模块归属、实现现状。量大时交给只读子代理按主题并行摘录（PRD 一份、后端归属一份），要求每条带出处；关键结论回源抽查再用。
4. **定模块词表**：复制 `assets/data-0-meta.template.js` 为数据目录下的 `data-0-meta.js`，按本项目架构写模块词表（粒度到能回答「这件事到底是谁干的」，通常细到服务里的子模块）、全局说明和用词约定。同一个对象全篇只用一个名字，第一次出现给定义。
5. **写讲解**：每屏一个视图、每个功能点一张卡，写进 `data-1-*.js` 起的数据文件（字段与格式见 `reference.md` §一，写法见 §二）。核心只有三句：讲解不是翻译；不写 PRD 编号和规格腔；设计目标不写成现状。
6. **构建与自检**：`node <skill>/assets/check.js <原型> <数据目录>` 静态检查通过后，`python3 <skill>/assets/build.py <原型> <数据目录> <产出.html> --title "<标题>"`；在浏览器打开产出，「目录 › 逐页自检」全部通过，再抽几屏截图目检圆点位置和卡片排版。
7. **复审**：照 `docs/PROJECT-GUIDE.md`「落盘前复审」换一个模型只读复审，本 skill 在构建之后、展示之前做（要先看成品）。除可读性六条外，重点查事实：卡片数字对原型源码，规则与阶段对 PRD，现状对设计与代码，改写有没有丢掉「按设计」「目标是」这类限定。清单逐条处置后复核，直到没有仍然成立的问题（清单见 `reference.md` §四）。
8. **交付**：告诉用户产出位置、覆盖了哪些屏幕、几个功能点、复审结论，以及原型与 PRD、设计不一致的要点（它们已写进各卡「注意」）。

## 拍板点

- 纳入哪些屏幕与抽屉（第 1 步）。
- 模块词表的粒度（第 4 步），以及项目没有后端时「归属模块」「现状」两栏写不写。
- 复审里动到结论的发现：例如「现状」判定有分歧，带给用户定，不自己改。

## 不要做

- 不改原型原文件，不改 PRD；原型或 PRD 本身的问题写进卡片「注意」并在交付时列出。
- 不往卡片里写接口路径、契约编号、源码文件名、PRD 编号——追问时的依据留在对话和复审清单里。
- 不为凑结构编内容：原型里找不到的数字不写，来源没说的事实不写，推断必须标明。
- 不重写引擎来适配某一份原型；确需扩展（例如屏幕识别），改 `assets/` 并同步回 projkit。

## 原型改版

讲解数据和原型分开存放，改版不用从头写：

1. `node <skill>/assets/check.js <新原型> <数据目录>`：列出找不到的屏幕标签、锚点文本和跳转步骤。
2. `python3 <skill>/assets/build.py <新原型> <数据目录> <产出.html> --title "<标题>"` 重新注入。
3. 浏览器打开产出，「目录 › 逐页自检」。
4. 只改失效条目的锚点或跳转；原型新增的功能补卡，删掉的功能删卡；改动过的卡走第 7 步复审。
